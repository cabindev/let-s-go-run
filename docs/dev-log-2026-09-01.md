## 5) ระบบสแกน QR รับเสื้อ/ของที่ระลึกหน้างาน (ฟีเจอร์ใหม่)

แยกเป็น 2 ระบบ ไม่ผูกกัน:

### ฝั่งเว็บ (`activerun`)
- เพิ่ม `Registration.pickupStatus` (`PENDING` / `PICKED_UP` / `SHIPPED`), `pickupAt`, `shippingTrackingNo`
- `app/api/checkin/[id]/route.ts` — API 2 endpoint (`GET` ดูข้อมูล, `POST` ยืนยันรับ/ส่งไปรษณีย์) ป้องกันด้วย `CHECKIN_API_SECRET` (รูปแบบเดียวกับ `CRON_SECRET` เดิม) — ปฏิเสธถ้ายังไม่จ่ายเงิน
- `lib/checkin-qr.ts` — สร้าง QR code เข้ารหัส `registration.id` (ไม่ซ้ำกันทุกการสมัคร แม้คนเดียวกันสมัครหลายงาน)
- หน้าจ่ายเงินสำเร็จ (`/payment/[id]`) โชว์ QR + เลข BIB ให้ผู้สมัคร
- หน้ารายการแอดมิน + Excel export โชว์สถานะรับของเพิ่ม
- **ทดสอบแล้ว**: auth reject, 404, happy path (PICKED_UP), SHIPPED พร้อมเลขพัสดุ, ปฏิเสธรายการที่ยังไม่จ่ายเงิน — ผ่านหมด
- **สถานะ: ทำเสร็จบนเครื่อง local เท่านั้น ยังไม่ได้ push ขึ้น production**

### โปรเจกต์แยกใหม่ `ludtong-checkin` (Python, อยู่ที่ `/Applications/MAMP/htdocs/ludtong-checkin`)
- เปิดกล้อง (OpenCV + pyzbar) สแกน QR → เรียก API ของเว็บหลักเพื่อดู/ยืนยันข้อมูล — **ไม่แตะฐานข้อมูลโดยตรง**
- ปุ่มควบคุม: `P` รับที่บูธ, `S` ส่งไปรษณีย์ (ถามเลขพัสดุ), `R` สแกนใหม่, `Q` ออก
- ไฟล์หลัก: `main.py`, `checkin/scanner.py`, `checkin/api_client.py`, `checkin/ui.py`, `README.md`
- **ทดสอบแล้ว**: logic เรียก API ผ่าน `api_client.py` โดยตรง (ไม่ผ่านกล้อง) ผ่านหมด — ยังไม่เคยทดสอบกับกล้องจริง

### ⚠️ ช่องโหว่ที่พบ (ยังไม่แก้)
งานที่ **ไม่มีค่าสมัคร (ฟรี)** จะ redirect ผู้ใช้ออกจากหน้า `/payment/[id]` ก่อนถึงจุดสร้าง QR เสมอ — ผู้สมัครงานฟรีจึง**ไม่มีทางเห็น QR ของตัวเองเลย** ทั้งที่ได้ BIB เหมือนกัน ต้องเพิ่มจุดแสดง QR ที่อื่น (เช่นหน้ารายละเอียดกิจกรรม หรือหน้าโปรไฟล์) สำหรับเคสนี้
